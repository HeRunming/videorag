# Construct-validity offline forms

The executable templates are generated by:

```bash
python tools/construct_validity_packet.py \
  --registry data/rehearsal_plan/construct_validity_example_registry.json \
  --sample /path/to/selected_sample.json \
  --output-dir /path/to/portable_packet
```

Normal packet creation timestamps the governance snapshot at runtime. Checked-in
blank examples must instead pass an explicit RFC 3339 timestamp with
`--generated-at`; use the same fixed value on every regeneration so the packet
and its governance hashes are byte-deterministic. This fixture-only control
does not freeze assignments or authorize distribution.

Generated packets contain four independent pre-adjudication annotation
directories, one adjudication directory, and one
`blind_post_adjudication_saturation_auditor` directory per family under
`reviewer_packets/`. Six distinct people are required. The coordinator must
distribute only the assigned role directory; this prevents the blind finder
from seeing preferred evidence/SES, prevents validators from reading one
another's decisions, and prevents the saturation auditor from seeing the
accepted SES ledger, preferred SES, machine ranks, or validator/adjudicator
decisions.

The generated packet also contains two coordinator-only governance artifacts:

- `coordinator/reviewer_assignments.json`
- `coordinator/source_exposure_ledger.json`

The assignment ledger is initially `DRAFT_NOT_DISTRIBUTABLE`, has null
reviewer IDs, and must not be frozen by inventing identities. Before
distribution, enter real pseudonymous identities and assignment timestamps,
record known prior exposure events in the exposure snapshot, then run:

```bash
python tools/construct_validity_packet.py \
  --output-dir /path/to/portable_packet \
  --freeze-existing-packet \
  --frozen-at 2026-09-23T23:30:00+00:00
```

Freezing fails closed on within-family role reuse, a blind-role conflict caused
by another family in the same source group, an adjudicator/author conflict
within a source group, or an invalid exposure ledger. Every later packet
access must be appended as a hash-chained `review_event`. The importer requires
an event matching every completed role and verifies that actual reviewer IDs
match the frozen assignments.

The saturation auditor starts only after adjudication is frozen. Their form
records chronological full-source coverage, search methods and queries, exact
new-route intervals/modalities/lineage, and whether the family must reopen.
Any new sufficient route blocks H2 until repair, readjudication, and a fresh
independent saturation audit. The coordinator supplies
`frozen_adjudication_sha256` as `sha256:<hex>` for the completed adjudication
file; the importer rejects a later-modified or mismatched adjudication. Blank
forms have:

```text
completion_status=not_started
human_gold_at_assignment=false
```

They deliberately contain no prefilled human answers. The JSON schemas in
`docs/spec/construct_validation_annotation_schema.json` and
`docs/spec/construct_validation_adjudication_schema.json`, plus
`docs/spec/construct_validation_saturation_audit_schema.json`,
`docs/spec/construct_validation_reviewer_assignment_schema.json`, and
`docs/spec/construct_validation_source_exposure_ledger_schema.json`, are
normative.

After offline completion, copy the packet back and run:

```bash
python tools/construct_validity_import.py \
  --packet-dir /path/to/completed_packet \
  --output /path/to/restricted_import_report.json
```

Checked-in blank dry-run reports may likewise use `--generated-at` to make the
example byte-deterministic. Real imports should omit it and retain the runtime
timestamp.

Only a successful import may derive `H1_HUMAN_VALIDATED` or
`H2_HUMAN_ADJUDICATED_GOLD`; filenames, handwritten status fields, or machine
confidence cannot promote a record.
